## 3. 现状诊断（为什么会卡、为什么会漏）

当前启动路径：`desktop.js` 的 `boot()` 无条件 `scanNow('boot')` → 主进程同步 `scan.scanRoots()`。

扫描器本身：

- 从若干「扫描根」递归 `readdirSync`，深度 12
- 看见 `hyperframes.json` 就把该目录当工程，**不再往下走**
- 每个工程再同步读 `package.json` / `BRIEF.md` / `index.html` / 封面图
- 界面线程要等整轮结束
- 没有进度、没有取消令牌、没有上次结果缓存

漏扫原因：

- **不是** walker 在已选根里漏文件。那个 videos 目录里 5 个工程都有 `hyperframes.json`
- **是** 默认只扫 `C:\Users\M` 一带，`C:\1AI` 根本不在范围内
- 后来用 `EXTRA_ROOT_CANDIDATES` 特判补上，换一个盘符/路径仍会漏

结论：卡顿来自同步全量遍历 + 解析；漏扫来自「先指定根再走路」，不是没装 Everything 才「扫丢文件」。要同时治这两件事，必须改成「先按文件名定位，再按需读工程」。

## 4. 开源调查：Everything 同类技术

Everything（voidtools）本身**不是开源**。它快，是因为：

1. 读 NTFS 的 **MFT**（`FSCTL_ENUM_USN_DATA`），不递归进每个文件夹
2. 再用 **USN Change Journal** 增量维护，文件一改索引就更新
3. 只索引名字和路径，不读文件内容

下面按「能不能借、借什么」分类。

### 4.1 真正同类（MFT / USN，Windows）

| 项目 | 技术 | 许可 | 评价 | 我们怎么用 |
| --- | --- | --- | --- | --- |
| [usn-journal-rs](https://github.com/wangfu91/usn-journal-rs) | Rust，枚举 MFT + 读/监视 USN | MIT | API 干净，维护正常 | **首选学习对象**；若做自有引擎，按它的调用方式写小型 helper |
| [MFTIndexer](https://github.com/Laxyny/MFTIndexer) | C++，`FSCTL_ENUM_USN_DATA`，可出 JSON/DLL | MIT | 思路对，项目很小 | 只参考接口，不整仓搬进来 |
| [winindex](https://github.com/rajeshsub/winindex) | MFT 扫描 + USN / `ReadDirectoryChangesW` 预留 | 开源 | 有管理员特权走 MFT，否则退回 FindFirstFile | 和我们需要的降级策略一致 |
| [PulseFS](https://github.com/ahmetburakcoskun/PulseFS) | C++，MFT 初建 + USN 实时同步 | 开源演示 | 声称约 80 万文件 / 2 秒 | 当架构参考，不嵌整套搜索 UI |
| [omni-search](https://github.com/Eul45/omni-search) | Tauri + C++ USN/MFT | 开源 | 桌面搜索完整产品 | 太重，不集成 |
| [UltraFastFileSearch / UFFS](https://github.com/skyllc-ai/UltraFastFileSearch) | Rust，直接读 MFT + 常驻 daemon | MPL-2.0 | 很完整，甚至对标 Everything | 体量过大，不绑进 Electron |
| [UltraSearch](https://github.com/Dicklesworthstone/ultrasearch) | Rust，MFT + Tantivy 全文 | 开源 | 文件名+内容搜索 | 我们不需要全文，过重 |
| [MiniThing](https://github.com/AlanoSong/MiniThing) | C++/Qt + USN + SQLite | MIT | 中文 Everything 仿制品 | 可看 USN→SQLite 的落盘方式 |
| [FastFileSearch](https://github.com/ChrisS85/FastFileSearch) | C++ USN DLL | 老项目 | 2010 年代，少维护 | 不采用 |
| [yuzhengyang/Everything](https://github.com/yuzhengyang/Everything)、EverythingCSharp、EverythingSZ | 教学向 USN 示例 | 教学 | 能看懂 API，不能当产品依赖 | 只当文档 |

共同限制：**读 MFT / USN 通常要管理员权限**；只覆盖 NTFS（ReFS 没有 MFT）。这是 Everything 也面对的取舍。

### 4.2 借已有索引，而不是自己当 Everything

| 项目 | 做法 | 评价 | 我们怎么用 |
| --- | --- | --- | --- |
| [voidtools ES](https://github.com/voidtools/ES) | 官方 CLI，问正在运行的 Everything | Everything 免费非开源；CLI 可合法调用 | **第一优先加速通道**：查 `hyperframes.json` |
| [ib-everything](https://github.com/Chaoses-Ib/ib-everything) | Rust/C++ 重写 Everything IPC SDK | 比每次拉起 `es.exe` 更省 | 若 Node 调 CLI 不稳，再考虑 |
| [everyfile](https://github.com/LouisGameDev/everyfile) | 纯 Python ctypes IPC，无 DLL | 证明 IPC 不必官方 DLL | 思路可借鉴 |
| everything-mcp / Codex Everything skill | Agent 调 `es.exe`，避免自己扫盘 | 和我们要解决的是同一类浪费 | 产品里做正式适配器，不做成 Skill |

本机若已开 Everything，查全盘 `hyperframes.json` 通常几十到两百毫秒级，比递归扫 `C:\Users\M` 快两个数量级。用户没装 Everything 时必须有自己的后路。

### 4.3 看起来像、其实不是同一类

| 项目 | 实际做法 | 结论 |
| --- | --- | --- |
| FSearch、ANGRYsearch | Linux 上先遍历再建内存库，**受 Everything 启发但没有 NTFS USN** | 不能解决 Windows 全盘秒级定位 |
| Recoll、DocFetcher | 内容全文索引 | 太慢、太重，和找工程标记无关 |
| locate / mlocate / plocate | 定期 `updatedb` 遍历 | Linux 方案；更新本身仍要走路 |
| fd / ripgrep | 更快的遍历，仍是遍历 | 可作 fallback 加速，不能当主引擎 |
| WizTree / JAM UltraSearch | 商业 MFT 工具 | 不集成 |

### 4.4 调查结论（写入实现约束）

1. **不要**把 PulseFS / UFFS / omni-search 整仓嵌进 HyperFramesSpace。
2. **不要**再靠「多写几个硬编码根」防漏扫。
3. **要**借 Everything 的能力（若本机有），并自建「只找 `hyperframes.json`」的轻量定位器。
4. 自建定位器学的是 `FSCTL_ENUM_USN_DATA` + USN 增量，参考 `usn-journal-rs` / `MFTIndexer` / `winindex`，只搜一个文件名，不做成通用搜索引擎。
5. 没管理员、没 Everything 时，异步遍历必须仍可用，且默认范围是**所有本地固定磁盘**，而不是只有 `C:\Users\M`。

## 5. 产品方案

### 5.1 启动体验

```
打开软件
  → 立刻显示上次目录（缓存），界面可点、可搜
  → 若「启动时自动扫描」为开：后台扫，顶栏/状态栏出进度条和「取消」
  → 取消：停后台任务，目录停在当前结果，并把「启动时自动扫描」改为关
  → 之后只在点「扫描目录」时再扫
```

卡顿期间主窗口不得假死。扫描必须离开同步 IPC，改成可取消的后台任务 + 进度事件。

### 5.2 设置（新增 / 调整）

| 项 | 说明 | 默认 |
| --- | --- | --- |
| 启动时自动扫描 | 与现有「定时扫描」分开 | **关**（打开先看上次结果） |
| 扫描范围 | 仅已登记扫描根 / **所有本地固定磁盘** | 所有本地固定磁盘 |
| 扫描引擎 | 自动 / Everything / 系统索引 / 文件夹遍历 | 自动 |
| 定时扫描 | 沿用现有 关/30s/1/5/15 分钟 | 关 |

「自动」引擎顺序：

1. Everything 正在运行 → 用它查 `hyperframes.json`
2. 用户允许管理员索引，且已建过系统索引 → 读本地 MFT/USN 索引
3. 否则异步遍历（有进度、可取消）

扫描根仍保留：用来收藏、过滤、侧栏展示，**不再是唯一发现手段**。

### 5.3 进度条要显示什么

- 阶段：定位工程 / 读取工程 / 补封面
- 数字：已找到 N 个 · 已读 M/N · 当前盘符或目录
- 引擎名：Everything / 系统索引 / 文件夹遍历
- 按钮：取消

取消只停扫描，不关软件，不清已显示的库。

### 5.4 防漏扫规则

工程身份不变：目录里有 `hyperframes.json`。

改变的是发现方式：

- 全盘（或全部固定盘）按**文件名**找 `hyperframes.json`
- 再映射到工程目录
- `C:\1AI\1cursorfull\CLAW8Final\videos` 不再需要特判
- 继续跳过 `node_modules`、`.git`、`Windows`、`$Recycle.Bin` 等
- 一个父目录下多个标记：每个都是独立工程（现有逻辑保留）

## 6. 技术架构

分成两段，禁止再「边走路边把 HTML 全部读完再一次性返回」。

```
┌──────────────────────────────────────────┐
│ 1. Locator  只找 hyperframes.json 路径     │
│    Everything → 自有 USN/MFT → 异步遍历    │
└──────────────────┬───────────────────────┘
                   ▼
┌──────────────────────────────────────────┐
│ 2. Hydrator 按路径读 BRIEF / pin / 封面    │
│    增量推送到界面，可取消                    │
└──────────────────────────────────────────┘
```

### 6.1 缓存

路径建议：`%APPDATA%\HyperFramesSpace\catalog-cache.json`

写入：工程列表摘要、扫描时间、引擎、范围。  
启动先渲染缓存，后台扫描用新结果替换，并标「尚未刷新」。

### 6.2 Everything 适配器

- 检测托盘 / IPC 窗口 / `es.exe`
- 查询：`hyperframes.json`（只要文件）
- 把命中路径去重成工程目录
- **不打包 Everything**，也不强制用户安装
- 设置里可看到：已连接 Everything / 未安装

### 6.3 自有系统索引（可选，需管理员一次）

目标不是通用 Everything，只建「`hyperframes.json` 路径表」。

建议实现：

- 单独小助手（Rust 用 `usn-journal-rs`，或 Node + `koffi` 调 `DeviceIoControl`）
- 首次：对每个 NTFS 盘 `FSCTL_ENUM_USN_DATA`，过滤文件名
- 之后：从上次 USN 续读，处理新建/重命名/删除
- 索引落在用户数据目录
- 没提权就跳过，走遍历，并在右下角说明「未开系统索引，扫得会慢一些」

第一期可以只做「一次性 MFT 枚举 + 文件缓存」，USN 常驻监视放到 1.0.5，以免 1.0.4 范围爆炸。

### 6.4 遍历后路（必须有）

- `fs.promises` 异步，限并发（建议 8）
- 可取消的 `AbortSignal`
- 按盘进度：已访问目录数 / 已找到标记
- 范围=全盘时从固定盘根走，跳过系统目录
- 找到标记立即交给 Hydrator，界面先出卡片再补封面

### 6.5 主进程 API 调整

现有 `desktop:scan` 同步返回整表，改为：

- `scan:start` `{ reason, scope, engine }`
- `scan:cancel`
- 事件 `scan:progress` / `scan:item` / `scan:done` / `scan:error`
- `catalog:loadCache`

设置新增：`autoScanOnLaunch`、`scanScope`、`scanEngine`。

## 7. 分阶段实施

### 阶段 A — 先不卡（必做）

- 启动读缓存，界面立即可用
- 扫描改异步，进度条 + 取消
- 「启动时自动扫描」默认关；取消一次即写入关
- 手动「扫描目录」仍完整扫
- 解析与遍历拆开，先出卡片

完成标准：冷启动 2 秒内能点库；扫描中窗口不假死。

### 阶段 B — 先找全（必做）

- 默认范围改为所有本地固定磁盘
- 只按 `hyperframes.json` 定位
- 去掉对 `CLAW8Final\videos` 的硬编码依赖（可留作展示用示例，不再当发现逻辑）
- 右下角说明本次用了哪种引擎、找到多少、是否可能受权限影响

完成标准：不把 `C:\1AI\...` 写进代码也能扫到那 5 个工程。

### 阶段 C — Everything 加速（必做，有则用）

- 自动检测并查询 Everything
- 设置里显示连接状态
- 失败自动降级，不弹致命错误

完成标准：本机开着 Everything 时，定位阶段亚秒级。

### 阶段 D — 自有 MFT 索引（建议做，可标实验）

- 设置里「建立系统索引（需管理员）」
- 一次性枚举 + 缓存
- 无管理员时隐藏或灰掉，文案说清楚

完成标准：不装 Everything、但同意提权时，全盘定位也是数秒级，不是数分钟。

### 阶段 E — 发布

- 版本号 1.0.4
- 安装包仍为 `HyperFramesSpace.exe`
- 中英 i18n
- 测试：缓存启动、取消、全盘找到 `C:\1AI\...`、Everything 开/关、无管理员降级
- 推 GitHub，Release 只留新 exe

## 9. 风险

| 风险 | 处理 |
| --- | --- |
| 读 MFT 要管理员 | 做成可选；默认走缓存 + Everything + 遍历 |
| 杀毒软件拦截卷句柄 | 助手独立进程，失败即降级 |
| Everything 未运行 | 检测 IPC，失败换引擎 |
| 全盘遍历仍可能慢 | 所以必须有进度和取消；默认启动不自动扫 |
| 缓存过期 | 状态栏标「未刷新」；手动扫一次即更新 |
